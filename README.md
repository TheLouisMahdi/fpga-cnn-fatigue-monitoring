## Overview

This project is a **hardware-software co-design prototype** for fatigue monitoring.

The goal is **not** to replace Python with FPGA. The real goal is **Python + FPGA co-processing**:

- Python handles camera input, OpenCV frame processing, MediaPipe FaceMesh, ROI extraction, EAR / MAR / PERCLOS, logging, and the final fatigue-state decision.
- FPGA acts as a parallel **CNN-style feature extraction accelerator** for small grayscale ROI images generated by Python.

The FPGA side currently focuses on fixed-kernel convolution and verification against a Python golden reference model. It is not a full trainable CNN accelerator and it is not a medical diagnosis system.

## FPGA Processing Pipeline

The FPGA accelerator uses a lightweight CNN-style pipeline:

```text
32x32 grayscale ROI
        |
        v
fixed 3x3 convolution kernels
        |
        v
ReLU + clipping
        |
        v
2x2 MaxPool
        |
        v
18-feature vector per ROI
```

One implemented kernel is a vertical edge-detection kernel:

```text
-1   0   1
-1   0   1
-1   0   1
```

For a `3x3` pixel window:

```text
p00  p01  p02
p10  p11  p12
p20  p21  p22
```

The simplified hardware equation is:

```text
conv = (p02 + p12 + p22) - (p00 + p10 + p20)
```

This keeps the first accelerator prototype simple and FPGA-friendly.

## FPGA Accelerator Verification

This repository verifies the **FPGA accelerator side** of the Python + FPGA fatigue monitoring project.

ModelSim does **not** simulate the camera, Python, OpenCV, MediaPipe, or full fatigue-state decision logic. It only verifies the RTL feature extractor.

### Python generates

```text
FPGAp/mem/left_eye.hex
FPGAp/mem/right_eye.hex
FPGAp/mem/mouth.hex
```

### Verilog / ModelSim generates

```text
FPGAp/mem/fpga_features_left_eye.txt
FPGAp/mem/fpga_features_right_eye.txt
FPGAp/mem/fpga_features_mouth.txt
```

### Python golden model generates

```text
FPGAp/mem/python_features_left_eye.txt
FPGAp/mem/python_features_right_eye.txt
FPGAp/mem/python_features_mouth.txt
```

### Expected comparison goal

```text
left_eye:  MATCH
right_eye: MATCH
mouth:     MATCH
```

## Verification Flow

```text
Python extracts ROIs from camera frame
        |
        v
Python writes left_eye.hex / right_eye.hex / mouth.hex
        |
        v
ModelSim runs FPGA RTL accelerator
        |
        v
Verilog writes fpga_features_*.txt
        |
        v
Python golden_model.py writes python_features_*.txt
        |
        v
Compare FPGA output with Python golden reference
        |
        v
MATCH / MISMATCH
```

Common mismatch causes:

| Cause | Explanation |
|---|---|
| Kernel mismatch | Python and Verilog use different fixed kernels |
| Addressing mismatch | ROI flattening order differs from RTL memory access order |
| Signed mismatch | Verilog signed arithmetic differs from Python integer behavior |
| ReLU / clipping mismatch | Negative or overflow values are handled differently |
| Pooling mismatch | MaxPool window order or stride differs |
| File path mismatch | ModelSim is reading or writing the wrong `mem` path |

## Running the Python Side

Install dependencies:

```bash
pip install opencv-python mediapipe numpy pandas openpyxl
```

Run from the `python/` folder:

```bash
cd python
python main.py
```

Python is responsible for generating FPGA ROI input files periodically based on `LOG_INTERVAL_SEC`.

---

## Running the FPGA Simulation

After Python has generated the ROI HEX files, run ModelSim from `FPGAp/sim`:

```tcl
cd FPGAp/sim
do run.do
```

The simulation script verifies the FPGA accelerator and writes `fpga_features_*.txt` files into `FPGAp/mem`.

## What This Project Is Not

This project is not:

- A full YOLO or object detection system
- A full trainable CNN running completely on FPGA
- A complete medical diagnosis tool
- A replacement for Python-based computer vision processing
- A ModelSim simulation of the whole camera + Python system

It is a **Python + FPGA co-processing project** where FPGA accelerates parallel feature extraction and Python remains responsible for preprocessing, verification, and final fatigue logic.
