## Project Summary

This project is a **Python + FPGA co-processing** system for fatigue monitoring.

The main idea is simple:

```text
Python handles vision, metrics, logging, and decision logic.
FPGA accelerates CNN-style feature extraction from small ROI images.
```

The project does **not** try to move the whole fatigue monitoring system into FPGA. Python remains responsible for camera input, OpenCV processing, MediaPipe FaceMesh, ROI extraction, EAR, MAR, PERCLOS, logging, and the final fatigue-state decision.

The FPGA side is a parallel CNN-style feature extraction accelerator. It receives three `32x32` grayscale ROI inputs generated by Python:

```text
left_eye
right_eye
mouth
```

For each ROI, FPGA generates an 18-feature vector that can be compared with the Python golden reference model.

## Python Pipeline

The Python side performs the real-time fatigue monitoring pipeline:

| Step | Description |
|---|---|
| Camera input | Reads webcam or IP camera frames |
| FaceMesh | Detects facial landmarks using MediaPipe |
| ROI extraction | Extracts left eye, right eye, and mouth regions |
| FPGA preprocessing | Converts each ROI to `32x32` grayscale format |
| Fatigue metrics | Calculates EAR, MAR, PERCLOS, blink count, yawn count, and microsleep count |
| Logging | Saves monitoring data into CSV/XLSX files |
| Golden model | Generates Python reference features for FPGA verification |
| Decision logic | Keeps final fatigue-state logic on the Python side |

## FPGA Accelerator Pipeline

The FPGA side is designed as a lightweight CNN-style feature extractor.

```text
32x32 grayscale ROI
        |
        v
fixed 3x3 convolution kernels
        |
        v
ReLU + clipping
        |
        v
2x2 MaxPool
        |
        v
feature summary
        |
        v
18-feature vector per ROI
```

One fixed kernel used in the current prototype is a vertical edge-detection kernel:

```text
-1   0   1
-1   0   1
-1   0   1
```

For a `3x3` pixel window:

```text
p00  p01  p02
p10  p11  p12
p20  p21  p22
```

The hardware-friendly equation is:

```text
conv = (p02 + p12 + p22) - (p00 + p10 + p20)
```

This keeps the prototype simple and suitable for FPGA implementation because the operation can be implemented with additions and subtraction.

## Feature Order

Each ROI produces exactly 18 features. The feature order must remain identical between Verilog and `golden_model.py`.

## How to Run the Python Side

Install dependencies:

```bash
pip install opencv-python mediapipe numpy pandas openpyxl
```

Run the Python pipeline:

```bash
cd python
python main.py
```

The Python pipeline periodically saves ROI HEX files and Python golden feature files based on `LOG_INTERVAL_SEC`.

---

## How to Run the FPGA Simulation

After Python has generated the ROI HEX files, run ModelSim from `FPGAp/sim`:

```tcl
cd FPGAp/sim
do run.do
```

The simulation script compiles the RTL modules, runs the final all-ROI accelerator testbench, and writes the FPGA feature output files into `FPGAp/mem`.

Then run the Python comparison:

```bash
cd python
python golden_model.py
```

## Remaining Work

For a simulation-based academic prototype, the main remaining work is:

1. Run Python and generate fresh ROI HEX files.
2. Run `FPGAp/sim/run.do` in ModelSim.
3. Confirm the three `fpga_features_*.txt` files are generated.
4. Run `python/golden_model.py`.
5. Confirm `left_eye`, `right_eye`, and `mouth` all show `MATCH`.
6. Capture waveform screenshots and terminal output for documentation.
7. Add screenshots, waveform images, and a short demo section to the README or report.

For a real hardware deployment, the remaining work is larger:

1. Add UART or another Python to FPGA data-transfer interface.
2. Add a final hardware top module for board-level integration.
3. Assign FPGA pins and clock constraints.
4. Program the Cyclone IV board.
5. Send ROI data from Python to FPGA in real time.
6. Receive feature vectors back from FPGA.
7. Compare real FPGA outputs with Python golden features.
8. Optimize memory access and consider line-buffer streaming.

## What This Project Is Not

This project is not:

- A full YOLO or object detection system
- A full trainable CNN running completely on FPGA
- A replacement for Python-based computer vision processing
- A ModelSim simulation of the whole camera and Python system
- A medical diagnosis tool

It is a **Python + FPGA co-processing project** where FPGA accelerates parallel feature extraction and Python remains responsible for vision preprocessing, verification, logging, and final fatigue logic.
